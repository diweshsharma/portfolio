# Portfolio Product Specification

## Objective

Create a recruiter-facing AI/ML Engineer portfolio that demonstrates
real engineering ability rather than simply displaying a resume online.

The website should make the candidate's strongest technical work easy
to understand and explore.

---

# Target Audience

Primary:

- AI/ML recruiters
- software engineering recruiters
- engineering managers
- AI/ML engineers
- technical interviewers

Secondary:

- developers
- collaborators
- other students

---

# Recruiter Experience

The recruiter should be able to quickly answer:

1. Who is this candidate?
2. What type of engineer are they?
3. What technologies do they actually use?
4. What are their strongest projects?
5. Can they build production systems?
6. Where is the resume?
7. Where is the GitHub?
8. How can they contact them?

---

# Information Architecture

Recommended sections:

1. Hero
2. About / Engineering Profile
3. Featured Projects
4. Technical Skills
5. Experience / Education
6. Engineering / AI Capabilities
7. Resume
8. Contact
9. Ask AI

The final information architecture may be changed after analyzing the
resume and discussing it with the user.

---

# Hero

The hero should immediately communicate:

- candidate name
- engineering identity
- AI/ML specialization
- concise positioning statement
- strongest technical areas
- primary CTA
- resume CTA
- GitHub / LinkedIn access

Avoid generic statements such as:

"I am passionate about AI and technology."

Prefer specific positioning based on the resume.

---

# Projects

Projects are the primary proof of engineering ability.

Projects should be selected based on:

- technical depth
- relevance to AI/ML
- production thinking
- engineering complexity
- uniqueness
- recruiter value

Do not automatically show every project with equal visual weight.

Create:

- featured projects
- supporting projects

---

# Project Storytelling

For each important project, communicate:

## 1. Problem

What problem does it solve?

## 2. Solution

What did the candidate build?

## 3. Architecture

How do the major components interact?

## 4. Technical Decisions

Why were important technologies or approaches selected?

## 5. Implementation

What did the candidate actually build?

## 6. Challenges

What difficult engineering problems were encountered?

## 7. Results

Include metrics ONLY if supported by the resume or approved by the user.

## 8. Lessons

What engineering insight was gained?

---

# Skills

Skills must be evidence-based.

Organize skills into meaningful groups such as:

- Programming
- Machine Learning
- Deep Learning
- Generative AI
- RAG
- Agentic AI
- Backend
- Databases
- Cloud / DevOps
- Developer Tools

Do not use fake skill percentages such as:

Python — 95%

Instead, connect important technologies to actual projects.

---

# Evidence of Skill

Where useful, show relationships such as:

Python
→ Project A
→ Project B

RAG
→ Project A

FastAPI
→ Project B

This demonstrates actual usage rather than simply listing technologies.

---

# Resume

The resume should be easily accessible.

Do not duplicate the entire resume unnecessarily if the website already
communicates the same information.

The website should complement the resume.

---

# Content Integrity

Every factual claim must be traceable to:

- resume
- user-provided information
- user-approved information

If a potentially useful section requires missing information:

Ask the user.

Do not fill it with generic placeholder achievements.

---

# Anti-AI-Slop Rule

Avoid generic portfolio copy.

Do not repeatedly use phrases such as:

- passionate about AI
- cutting-edge technology
- innovative solutions
- transforming the future
- AI-powered everything
- leveraging state-of-the-art technology

unless they are genuinely relevant.

Prefer concrete engineering language.

---

# Content Approval

Before publishing major portfolio content derived from the resume:

Show the user the extracted information and ask for corrections.

The user must be able to approve:

- profile positioning
- project descriptions
- skills
- achievements
- metrics
- experience descriptions
